what is it

A directed acyclic graph of tasks. Dependencies are edges. Completing a task unblocks downstream work. A background service auto-dispatches AI agents to ready tasks.

Plain text storage (.workgraph/graph.jsonl). Git-friendly. No server. No account. Just a binary and a directory.

loop edges

Tasks can loop. Not everything is a straight line.

ci-run-tests → ci-fix-failures → ci-push-check ↺ ci-run-tests

When ci-push-check completes, it re-opens ci-run-tests. The whole chain resets. Iteration counter increments. Agents read previous logs and pick up where they left off.

$ wg loops

Loop edges: 2

  ci-push-check --[loops_to]--> ci-run-tests  [ACTIVE]
    iterations: 1/5  guard: none (always)

  test-loop-dummy --[loops_to]--> nonexistent  [ACTIVE]
    iterations: 0/2  guard: none (always)

Loop summary: 2 active, 0 exhausted

No dependency cycles detected.

Loop edges are separate from dependency edges. They don't affect scheduling. The DAG stays clean. Loops are evaluated at completion time only. Every loop requires max_iterations. No unbounded loops. Optional guards and delays control when they fire.

$ wg add "Run tests" --id ci-run-tests
$ wg add "Fix failures" --id ci-fix-failures --after ci-run-tests
$ wg add "Push check" --id ci-push-check --after ci-fix-failures \
    --loops-to ci-run-tests --loop-max 5

recursive prompting

Tasks create tasks create tasks.

Create a task that surveys the codebase, then spawns subtasks for each gap it finds. The coordinator dispatches agents to each subtask. When those complete, evaluation tasks spawn automatically. The whole thing recurses.

$ wg add "Survey codebase for gaps" --spawn-subtasks
$ wg service start --max-agents 4

# the survey agent runs, finds 3 gaps, creates subtasks:

Meta-tasks (assigner, evaluator, evolver) use the same mechanism. The system bootstraps itself. You define the shape of the work; agents fill in the details.

the agency system

Agents have roles (what they do) and motivations (why they do it). They get evaluated after each task. The evolver mutates and crosses over the best performers. Darwinian prompt engineering.

The synergy matrix shows which role+motivation combos perform best. b491d6c1 x 1caa4c3c averaging 0.93 across 63 tasks — that's the Rust Systems Programmer with the top motivation. The evolver sees this and creates more agents with that combo.

Roles define skills and desired outcomes. Motivations define acceptable trade-offs and non-negotiable constraints. Combine them into agents. Evaluate after every task. Evolve the population.

# the loop: assign → execute → evaluate → evolve → assign

$ wg assign implement-auth careful-coder
$ wg service start              # agent executes the task
$ wg evaluate implement-auth     # score: correctness, completeness, efficiency, style
$ wg evolve --strategy all       # mutate, crossover, retire, gap-fill

Six evolution strategies: mutation (tweak a role), crossover (combine two roles), gap analysis (find missing skills), retirement (remove underperformers), motivation tuning (adjust trade-off boundaries), and all (let the evolver pick).
